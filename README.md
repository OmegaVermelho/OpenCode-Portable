# OpenCode Portable

> A full AI coding agent in a terminal, running from any folder or USB drive.
> Plug in. Launch. Code. Take it anywhere.

This package wraps the Go **opencode** engine (from `opencode-main`) in the same
portable structure used by **OpenClaude Portable**: bundled binaries, a launcher
with provider setup, and all data redirected inside `data/`.

Nothing is written to the host machine: `HOME`, `USERPROFILE`, `XDG_CONFIG_HOME`,
`XDG_DATA_HOME`, and `XDG_CACHE_HOME` all point inside this folder.

---

## Quick Start

### Linux / macOS

```bash
git clone https://github.com/OmegaVermelho/OpenCode-Portable.git
cd OpenCode-Portable
chmod +x start.sh
./start.sh
```

### Windows

```bat
git clone https://github.com/OmegaVermelho/OpenCode-Portable.git
cd OpenCode-Portable
START.bat
```

You can also download the ZIP from GitHub and extract it anywhere.

On the first run the launcher asks for:

1. **Provider** (Anthropic, OpenAI, Gemini, OpenRouter, Groq, xAI, NVIDIA NIM, Local/Custom)
2. **API key** (verified when the provider is online)
3. **Model**

Settings are saved to `data/ai_settings.env` and reused on every launch. The
repository ships without API keys, so the first run always asks for one.

## Supported Providers

| Provider | Notes |
|---|---|
| **Anthropic Claude** | Claude 4 Sonnet/Opus, 3.7, 3.5 |
| **OpenAI** | GPT-4.1 family, o3, o4-mini, o1, GPT-4o |
| **Google Gemini** | Gemini 2.5 / 2.5 Flash / 2.0 Flash |
| **OpenRouter** | Includes `deepseek-r1-free` and Claude/GPT/Gemini routed models |
| **Groq** | Llama 3.3/4, DeepSeek R1 distilled, Qwen |
| **xAI** | Grok 3 family |
| **NVIDIA NIM** | Free tier from `build.nvidia.com` (Nemotron, MiniMax, DeepSeek...) |
| **Local / Custom** | Ollama, LM Studio, DeepSeek, any OpenAI-compatible API |

### NVIDIA NIM

Choose option **7** and paste an API key from `https://build.nvidia.com`.
The launcher verifies the key with a real 1-token completion, lists the models
and configures the local provider against `https://integrate.api.nvidia.com/v1`.
The default is `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning`. The catalog is
global: a listed model may not be enabled for your account; pick another if the
test returns 404.

### Local / Custom endpoints

Choose option **8** and enter a base URL:

| Server | Base URL |
|---|---|
| LM Studio | `http://localhost:1234/v1` |
| Ollama | `http://localhost:11434/v1` (started automatically if `ollama` is in PATH) |
| DeepSeek | `https://api.deepseek.com/v1` |

The launcher lists the models returned by `GET /v1/models`. If the server does
not expose that endpoint, type the model ID manually.

**Custom model IDs** are also supported for the native providers: choose
`Manual API model ID` in the model menu. The engine ships with extra support for
declaring models in `.opencode.json` (`providers.<name>.models`) and overriding
the OpenAI-compatible endpoint (`providers.<name>.baseURL`).

## How Portability Works

The launcher exports, before starting the engine:

```
HOME            -> data/home
USERPROFILE     -> data/home             (Windows)
XDG_CONFIG_HOME -> data/config
XDG_DATA_HOME   -> data/app_data
XDG_CACHE_HOME  -> data/cache
APPDATA         -> data/app_data         (Windows)
LOCALAPPDATA    -> data/local_app_data   (Windows)
```

The generated `data/home/.opencode.json` also pins the database directory to the
absolute path of `data/opencode`, so sessions never land in the project folder.
The file is regenerated on every launch; project-specific settings belong in a
`.opencode.json` inside the project (the engine merges it automatically).

API keys are stored unencrypted in `data/ai_settings.env` (permissions `600` on
Linux/macOS). Treat the drive accordingly.

---

## Security

- `data/ai_settings.env` and `data/home/.opencode.json` contain API keys in
  plain text. Both paths, and all runtime data under `data/`, are gitignored;
  the repository never ships with credentials.
- Before sharing a configured folder (ZIP/USB), delete `data/ai_settings.env`
  and `data/home/`, or run the setup again on the target machine.

## Engine Builds

Bundled binaries were built from the `opencode-main` source tree with these
small additions needed by the portable launcher:

1. `providers.<name>.models` registers custom model IDs at startup.
2. `providers.<name>.baseURL` overrides the OpenAI-compatible endpoint.
3. Local model discovery has a 3-second timeout and honors `LOCAL_MODEL`
   (including IDs missing from the `/v1/models` listing).
4. `LOCAL_CONTEXT_WINDOW` and `LOCAL_MAX_TOKENS` override the context window
   and output limit of local/custom models (NVIDIA NIM uses 131072/8192).
5. Local models default to `CanReason=false`, so the engine sends `max_tokens`
   instead of reasoning parameters not supported by most OpenAI-compatible
   servers; enable reasoning with `LOCAL_CAN_REASON=1`.

Rebuild everything with:

```bash
./tools/build_engine.sh
# or: OPENCODE_SRC=/path/to/opencode-main TARGETS="linux/amd64" ./tools/build_engine.sh
```

Requires Go 1.24+. The SQLite driver is pure Go, so builds are static and do not
need CGO.

The patched `opencode-main` source tree is not bundled. The prebuilt binaries in
`engine/` are ready to run; to rebuild, apply the changes documented in
`tools/ENGINE_PATCHES.md` to the upstream source and point `OPENCODE_SRC` at it.

## Notes

- `ripgrep` (`rg`) and `fzf` are optional. If present in `PATH` (or in
  `tools/bin/`), search and file pickers become faster; otherwise the engine
  falls back to its Go implementations.
- The engine is the archived Go opencode (`v0.0.55`). It supports the models
  compiled into the binary plus any model registered through the config.
- On macOS/Linux, the first run creates `data/`; you can copy the whole folder
  to another machine or USB drive and the settings travel with it.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `OpenCode engine not found` | Run `tools/build_engine.sh` or put the binary in `engine/opencode-<os>-<arch>/` |
| `could not verify the key` | Check the key/network or answer `y` to continue (useful offline) |
| NVIDIA `HTTP 000` | The request got no response: network/DNS/proxy or the model cold start exceeded the timeout. The launcher waits up to 90s and offers a retry. |
| NVIDIA `404 Not found for account` | The model is listed globally but not enabled for this key. Choose another model or request access. |
| NVIDIA `403 Authorization failed` | `/v1/models` is public, so listing works even with a bad key. The launcher now sends a 1-token test completion; 403 means the key is invalid/revoked or has no inference access. Generate a new key at `build.nvidia.com`. |
| Local model list is empty | Start LM Studio/Ollama; confirm `GET <base>/v1/models` works |
| TUI model seems old | Pick `Manual API model ID` and type the new model name |
| Ollama is slow | Use a smaller model; the engine trims context via `autoCompact` |
